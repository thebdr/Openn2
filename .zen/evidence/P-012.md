# P-012 - Template-builder pilot: evidence

## Spec review (2026-09-25) - the user's decisions
- Template editing happens INSIDE the Files tab (a template mode of the text editor), not in a dedicated window.
- Literal braces are written DOUBLED (`{{ }}`, Python's pairing), so a TIA pragma is writable. Landed in C-024 as
  phase A (2c1e755); refute round 17 HOLDS.
- ROW templates are fully editable too (their values are lint-checked and previewed like text lines).
- The shipped builtin templates.yaml is READ-ONLY. "Create project copy" writes
  `<project>/config_project/systems/<sid>/chain_reactions/templates.yaml` (tier 1 of the resolver), and is disabled
  when no project is open.

## Phase B (2026-09-25) - the Tk-free core
- `tempemplator.lint(templates, start=, fields=, tables=)` walks EVERY branch of every text template, evaluating
  nothing. It uses the renderer's own checks through shared helpers (`_use_problem`, `_column_problem`,
  `_end_value`, `_check_directive`, `_scan`), so there is one message per problem for render and lint.
  - A rule's context (`start` + `fields` + the hook's `tables`) adds the strict missing field, the unknown loop
    table and the loop-column check, carried into @use'd templates.
  - Every template is also walked without context, because another rule at another hook may use it.
  - Predicates stay lenient: an unknown name there is a WARNING. So are a `where` reading its own loop var
    (round 16's note), the empty hole `{}` and a braced literal `{{$x}}` (round 17's note 1).
- `lint_line` checks one line / row value: lone braces, hole syntax, missing fields, loop columns.
- `engine.lint(templates, rule, database, hooks)` judges every entry for its KIND (text / row shape + values /
  neither). With a rule it adds the rule's E1 scope and the rule's own problems (template=None): the wrong kind,
  a table absent at the hook, a hook never fired, a target that will not render. An absent source table does
  not flood every hole as missing.
- `engine.preview(rule, row_index, ...)` is ONE fire for one source row through the fire path's own steps
  (`_template_problem`, `_scope`, the condition, `_spawned` / `_file_output`, carved out of `_spawn_rows` /
  `_append_file` with semantics unchanged: a spec is still added before the next renders). Rows are stamped
  as `add_row` stores them (`Table.stamped`, the uid included).
  - test_template_builder compares previews with REAL fires: the same rows, the same file text + path, the
    same finding (type + detail).
- `System.reaction_hooks` maps each hook to the Database it sees, declared by the run-plan. For Siemens:
  before_300 -> None; after_300 -> staging's `staged_database` (declared once, used by `stage_iolist`) +
  validation_issues.
  - The smoke pins the declaration against the real fire: the same hooks in order, the same tables + columns.
  - That pin CAUGHT a first draft that left out validation_issues: the 300/320 legs attach it before
    after_300 fires. The 310-only leg does not - noted in the loader's docstring.
- `workbench/template_doc.py` is the document model:
  - It parses with the engine's loader (a YAML error = rx_templates_unreadable, located).
  - Positions come from a round-trip parse's marks: literal blocks exact, folded / escaped quoted approximate.
  - Two-layer spans: YAML outside the bodies, SCL (FileXY langs.json) under them, and the template layer read
    through `tempemplator.outline` / `brace_runs` / `hole_parts` - the display never re-derives the grammar.
  - `place` maps lint problems to document offsets; `completions` works at the cursor.

Tests:
- test_template_builder (10): lint finds every one of 25 renderer errors on the renderer's own line, plus the
  untaken branch; the context lint matches the strict render; preview == fire.
- test_template_doc (5): positions exact on the shipped authoring manual; highlight tags on their constructs;
  problems placed on the culprit's text; completions from the context only.

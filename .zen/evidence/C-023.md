# C-023 — Per-system GUI projection + multi-system routing (PL5 step 5)

Promoted from P-011 on landing, 2026-07-17. Branch `pl5`; parity reference stays `pl4` @ `16ef215`.

## What landed (the moves, in order)

1. **Phase/Sub/PhaseSet became CONTRACT types** (`pipeline5/systems/system_contract.py`).
   They cannot live in `workbench/phase_model.py` as PL4 had it: a System descriptor must
   instantiate a PhaseSet, and systems < workbench in the L1 layer order — the classes had to sit
   at (or below) the systems layer or every descriptor would import UPWARD. `PhaseSet` validates at
   construction (duplicate phase/sub numbers, run_plan naming non-runnable/duplicate phases) — a
   registry typo fails at system import, not at a button click. `run_plan` is EXPLICIT data, not a
   derivation: Siemens = `(300, 400, 500, 600, 700, 800, 900, 100)`, 200 Fill deliberately absent
   (it mutates the source document). `PhaseContext` gained the missing seams: `records` (the
   validation handler posts PRE-RENDERED structured records — a different queue event than a log
   line) and `halt` (the severity contract's run-halt flag).

2. **`safety/main.py` — the Siemens main routine** (the user's original framing: each system a
   folder with a "main" calling shared + custom functions). PHASES (the oracle-transcribed
   registry, handler keys now abstract — `"validation"`, not `"_run_validation"`) + the ten
   `run_x(ctx, only=None)` handlers ported verbatim from `App._run_*` with the seam substitutions
   (`self._emit → ctx.emit` etc.). A wired special names its handler key in `Sub.opens`
   (245 → `"risky_index"`) — the App's hardcoded `pb_risky_index` knowledge died.

3. **The LAST ratchet edge PAID** — `phases.fillout.document_fill` no longer imports
   `phases.staging`: `fill_out/_compute_fill/risky_index_fill/fill_script_type` take the CALLER's
   staged database; the stage→fill→re-stage wiring lives in `run_fill`/`run_risky_index` (the
   run-plan). `RATCHET = {}` in test_architecture_contracts.py; `test_ratchet_entries_still_real`
   forced the deletion. L2 is now clean with zero exceptions.

4. **app_main.py is a HOST**: resolves `self._systems` from the project meta (builtin → Siemens),
   dispatches through `self._system.handlers`, builds a `PhaseContext` per run. The 351-line
   handler block is gone. Open-target resolution order: `system.open_targets` →
   `system.output_layout.dirs()` → kernel targets.

5. **Meta consumption** (`project_manager`): `open_project` resolves `types` via the catalog;
   unknown → `UnknownSystemError` (pointed "this is a PIPELINE4 project" for the PL4-era ids —
   which are REGISTRY data, `catalog.PL4_LEGACY_IDS`, after L5 flagged the literals in the project
   layer); `auto_reopen` skips such projects. Multi-system routing: >1 meta type →
   `config.set_multi_system(True)` → `database_dir()`/`output_root()` gain `/<sid>`; single-system
   stays FLAT (the OP4 path contract). Toolbar selector visible only for multi projects;
   switching re-points `use_system` + rebuilds the phase bar (`PhaseBar.set_phases`).

## Bugs found and fixed IN PASSING (the step's honesty ledger)

- **`_run_reporting` called `engine.build(database)` without `system`** → RuntimeError at every
  phase-900 click since step 4d. The parity oracle CANNOT see this class (it drives the chain
  functions directly with hand-passed arguments); the new headless smoke runs the handlers' own
  wiring and would have gone red. Fixed in the port (`system=ctx.system`).
- **`coverage.project(database)` ran system-less in the GUI** while the oracle chain passes
  `system=SYSTEM` — the GUI's coverage report diverged from the oracle's. Now system-routed.
- **`error_mgmt` open target pointed at `error_management.csv`** — stale since the step-4 rename to
  `finding_treatments.csv`. Now `treatments.registry_path()` (single source).
- **`diag_config` open target called `config.diagnosis_dir()` which does not exist** (AttributeError
  swallowed by the click handler's try/except → permanent "could not resolve" WARN). Now a
  resolver-backed `SYSTEM.open_targets` fn (opens the folder actually supplying `diagnosis/*.csv`).
- **Toolbar brand said `PIPELINE4`** (verbatim PL4 port). Now PIPELINE5.
- test_project_manager.py still created projects with the PL4 id `siemens_plc_safety` as a dummy —
  meta validation would rightly refuse `save_as` re-opens. Updated to the taxonomy id.

emits RSLT, the source doc's mtime is untouched, and pins FIXTURE TRUTH the harness taught us:
**the playground carries two genuine duplicate I/O tags (`NET SAFETY 50!O65` / `51!O62`) the
shipped registry does not treat → phase 500's 510 leg HALTS (PLCTags is never written on a raw
FAIL; PL4 behaved identically — that is why parity never noticed).** A halt anywhere else, or 500
NOT halting, is a deliberate re-pin.

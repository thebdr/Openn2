# C-053 evidence - every Global-DB member a generated block references is declared

## The gap (2026-10-28, from the C-052 work)
The safety block builders spell some member names in code: the 03 zone cumulatives' labels (`ZONE_GROUPS`) and the
04_ESTOP power coil (`_power_enabled`). The DB members come from the project's own copy of
`datablocks/datablock_members.csv`, made when the project was created. In the C-052 session, a copy of FVT kept its
old `{$area} PB` rows and was regenerated by code that writes `<area> E-STOP_PUSHBUTTONS`. Its 03 Zone Cumulative
then wrote eight `"02_COM"."AREA x E-STOP_PUSHBUTTONS"` coils, and 04_ESTOP read them, while 02_COM declared
`AREA x PB`. The run passed: exit 0, 0 FAIL, coverage 0 ORPHAN / 0 UNPLACED. The 900 coverage's UNPLACED scans
only the diagnosis bindings and the interface expressions (`coverage.collect_outputs`); the block references are not
in it. TIA would only report the mismatch when compiling.

## The check
`pipeline5/phases/coverage/member_references.py`, called by `run_software` after `build_engine.build` and gated
together with the builders' own findings:
- What a block references:
  - a ready FC XML (03 Zone Cumulative), as `_ready_block_xml` renders it in memory: every variable of every network
    (`signal_paths.ready_networks`);
  - a template-filled block: each `software_block_members` row through its template network (the row's
    `TemplateType`), with the row's values put in (`signal_paths.template_variants` / `network_symbols`, pads kept);
  - a ready SCL (03_Diagnostic Nodes), as `_ready_block_scl` renders it: every `"db"."member"`
    (`SYMBOLS.find_bindings`), located by its `REGION`.
- What is checked: the references whose DB is in `db_blocks`, against that DB's `db_members`. The comparison is
  case-insensitive (TIA's names are; the 02 template writes `01_PushButton` for the DB `01_Pushbutton`). A Struct
  member ([[C-042]]) is `"db"."struct"."member"`. A part past a plain member is not checked. Instance DBs, PLC tags
  and the hand-kept DBs (`SPEED_STATE_REC`, `10_PN_NETWORK`, `06_Settings`) are never checked.
- What it raises: one `blk_undeclared_member` FAIL (phase 800) per block place and symbol, located
  `<block> / network n (title)`, `row n (comment)` or `REGION ...`. The detail names the symbol, the DB, and where
  the DB's members come from. The findings are recorded to validation_issues; `run_software` saves them, and 800
  halts before any block is written.
- Where it lives: the coverage chapter, because it reads the signal-paths wiring and L2 (chapters never import each
  other) keeps it out of `phases/software_blocks`.

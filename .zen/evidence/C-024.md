## What landed, and where (the blend homes)

- **`language/tempemplator.py`** — the recursive text renderer, named for the user's VBA tool
  (their FUH_DHL belt-code generator, studied 2026-07-16). Rebuilt on `language/expr` with the
  construct map 1:1 (the module docstring carries the full table). The original's guillemet/dollar
  split survives as @-directives (structure) vs {expr} holes (values). Holes render STRICT — a
  typo'd field is a located TempemplatorError(template, line), never a silent blank. `@if` branches
  are LAZY (scan-then-render-taken-only): a strict hole inside the untaken branch never evaluates —
  the guard pattern `@if present($x) … {$x.field}` works. The E3 upgrade the VBA could never do:
  `@for $row in <table> [where <pred>]` loops over SSOT rows.
- **`phases/chain_reactions/engine.py`** — the rule engine chapter. `compile_rules` validates each
  reactions.csv row (malformed → located ERRR, dropped); `fire(hook, database)` matches, spawns
  (`add_rows` with `spawned_by`+`source_uid` provenance) or appends (`file`, the ONLY mode — user
  decision), audits everything into `chain_reactions_log` (replaced per hook = the last run), records
  failure findings to validation_issues, saves. STRICT NO-OP on a rule-less hook.
- **Config**: Siemens ships `chain_reactions/reactions.csv` (header only — CSV has no comment
  syntax; an example row would compile as a live rule) + `templates.yaml` whose comments are the
  authoring manual and whose three entries are the VBA WORKED EXAMPLES (Ex.1 leaf line + loop var;
  Ex.2 structure template with counted loop + nested @use; Ex.3 the inline conditional as plain
  expr if()/present()/concat()) — executable reference, rendered for real by the test suite.
- **Hook wiring**: the SYSTEM RUN-PLAN (safety/main.py `run_staging`) fires `before_300` (no
  database yet — file rules only) and `after_300` (the freshly staged database). The P-009 draft
  said "kernel phase dispatch, no per-main code" — that pre-dated the blend: L2 forbids
  chapter-to-chapter calls and the step-5 architecture made the run-plan THE dispatch, so the
  hooks live there. One anchor for now; more anchors arrive with the config folds.

## Design decisions the draft left open (resolved here)

- **CSV columns**: `action` + `target` replace the draft's single `target_table` — the `file`
  action needs a PATH (expr-rendered, relative → under the project output root); the draft
  predated it. `source_table` empty = a FIRE-ONCE rule (e.g. a generated-file header).
- **Failure severity**: ERRR (skip the rule, continue, loud) per the severity taxonomy — FAIL
  would halt generation for a mis-authored optional rule; ERRR marks the output possibly
  incomplete without killing the run.
- **The log replaces per hook** (uid keys hook/rule/target): the Explorer shows the LAST run's
  audit, not an unbounded history; determinism preserved (no timestamps in the SSOT).

## Known boundary (deliberate)

An `after_300` `add_rows` spawn persists into the SAVED Database (Explorer-visible) but downstream
phases RE-STAGE from the source document — spawned `signals` rows do not yet flow into generation.
That absorption is the generated-signals FLAGSHIP, which the standing spec-review gate holds until
its own reviewed step. The engine's mechanics are complete and proven; the wiring depth grows there.

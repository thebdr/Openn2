### Everybody logins: limit and lifetime (2026-10-28)
Tool: `everybody_sessions.py` (scratchpad). It only calls `Api.Login` as Everybody (empty password),
`PlcProgram.Read "02_COM".AlwaysTRUE` and `Api.Logout`, and logs every token out at the end.

- **Limit:** 100 Everybody logins were held at once with no refusal (the test's cap). A read with the first
  token still worked while all 100 were open. All 100 logged out, and a fresh login worked afterwards. So
  the CPU allows at least 100 simultaneous Everybody sessions, far more than the browsers a plant opens.
- **Lifetime** (12:07-12:26 CPU time, 8 idle tokens each checked once, plus 1 token read every 5 s):
  - Idle checks: **valid after 60, 110 and 125 s; expired at 140, 200, 300 and 600 s**. An idle token lives
    about 2 minutes (between 125 and 140 s after its last use).
  - **An expired token answers exactly like no token:** HTTP 200 with
    `{"code": 2, "message": "Permission denied"}`. There is no separate "invalid token" error.
    Design consequence (M3, `rpc.js`): on code 2, log in again once and retry; only a second code 2 means
    Everybody lacks the right.
  - The token read every 5 s never expired. At about 19 min (12:26:26) one request failed with
    `RemoteDisconnected` (the CPU closed the HTTPS connection without a reply, over Wi-Fi), which ended the
    test before the 30-min check.
  - All 5 remaining tokens logged out, and a fresh login worked right after. The poller must treat a dropped
    connection like any lost connection (the backoff).

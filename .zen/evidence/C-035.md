# C-035 - A total row the template's data table shows stays its last row - evidence

## Origin (2026-10-09, P-020 from C-034 refute round 4)
The refuter edited the shipped MachineInterfaces template IN EXCEL to show the Total Row on `SORTER_SIGNALS`
(`ref="A1:Q32" totalsRowCount="1"`, `<autoFilter ref="A1:Q31"/>`; row 32: `Total` in A, a `count` on
`Signal Name Side 2` - `SUBTOTAL(103,SORTER_SIGNALS[Signal Name Side 2])` in Q). Projected with mirror elements
(3 BOOL `DOOR` signals at byte 20 + a WORD `SPEED` at 30, as FVT has) by the pre-fix 400c, re-run here:
- the table part: `ref="A1:Q50" totalsRowCount="1"`, `<autoFilter ref="A1:Q50"/>` - the "Total" row stranded
  on row 32 INSIDE the data, the block on 33..50, Excel's total row = the last block row;
- Excel 16 REFUSES the IF_ workbook and the scratch copy of FVT's I/O List 400e grafted it into (with
  `DisplayAlerts=False` a file needing repair makes `Workbooks.Open` raise: "Open method of Workbooks class
  failed").
`_append_custom_rows` took `interfaces._find_data_table`'s r2 - the table ref's last row - as the last DATA row.
The same helper feeds 400b's template readers (`template_native_elements`, `template_extent`,
`template_last_used_byte`): a total row with a label in the signal-name column would have become a template-native
signal (direction defaulting to Q), a label / value in the direction / offset columns a used byte.

## The choice: insert above the total row (not refuse)
Excel's own gesture for growing a table that shows its total row is "insert table rows above" it - the template
author's intent stays intact and nothing is refused. So `_find_data_table` returns the last DATA row
(`r2 - totalsRowCount`), and `_append_custom_rows` lays the block from the row after it (exactly where a table
without a total row gets it), first moving the total row (its cells in the table's columns, `move_range`, formulas
not translated) down by the block's height; the table ref ends on the moved total row, the autoFilter one row
above it (Excel's convention - the refuter's Excel-saved template has `ref A1:Q32` / `autoFilter A1:Q31`).
The totals Excel writes reference the whole column (`SUBTOTAL(10x,TABLE[column])`), so they cover the block with
no rewrite. Not promised (stated in the clause by "formulas as written"): a total-row formula a template author
typed with plain A1 ranges keeps those ranges.

# C-051 evidence - a document on another drive than the project is imported (GitHub issue #2)

## The failure (2026-10-26, issue #2 "Import doesn't work")
The issue's screenshot: the Documents tab (Italian UI), I/O List (current) =
`E:/BFVT_I-O LIST/BFVT_IO0011 - I-O List Induction lines - LOWER GR1_R1.2.xlsx`; after "Importa i documenti nella
cartella progetto" the status line reads `import failed: Paths don't have the same drive`.

## The cause
- `project_manager.import_documents` (main's lines 402-403, from the kernel move `d009b3f`, 2026-07-16) asked
  whether a configured document already lies inside the project with
  `os.path.commonpath([root]) == os.path.commonpath([root, configured])`.
- Windows' `ntpath.commonpath` does not answer for two paths on different drives - it raises. Reproduced with the
  repo venv (Python 3.12.10): `os.path.commonpath([r'C:\proj', r'E:\x.xlsx'])` -> `ValueError: Paths don't have
  the same drive`; the same for a UNC share (`\\localhost\C$\x`) and for the extended form (`\\?\C:\proj\x`).
- `workbench/documents_panel.py` `_import_documents` catches `(ValueError, OSError)` and shows `import failed:
  <error>`, so the whole import stopped on the first document on another drive - none was copied.

## The fix
`project_manager._inside(root, path)`: the same comparison, `False` on that `ValueError` (`# another drive on
Windows`, as `hardware_csv_export` and `creation_info_csv` already write it). A document on another drive takes the
outside branch: copied into `<project>/input_documents/current|previous/`, its path rewritten relative to the
params file's folder, `{source, mtime}` recorded; a file that does not exist is `missing`, its path kept. The
rewrite `os.path.relpath(target, config_dir)` that follows is then always between two paths inside the project.

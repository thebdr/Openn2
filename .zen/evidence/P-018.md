Project `C:\Projects\Pipeline4\FVT_PL4_Safety`, PL4 `pl4-fvt` @ 919a3b5, phases 300 -> 900 + 100 run on the I/O List
`8FVT_IO0100 IO List Safety R0.3` (2438 rows) and the C&E `8FVT Cause and Effect Matrix (V5) R0.1wip`. The check
(scratch script `verify_generated.py`) re-derives every expectation from the documents, never from the generator.

## What holds
- Tags (510): 724, one per typed I/O row, at the row's address, the row's designation in the name; no duplicate
  name or address, no stray tag.
- 02 EM Push Button: 74 calls; the 220 e-stops and both disconnectors each read exactly once into their own
  01_Pushbutton member; the 211 lamps wired to their own e-stop; one instance per call.
- 03 Zone Cumulative: 13 networks, each one AND box (no negation, cardinality = wired inputs, every operand
  resolves); all 230 C&E causes in exactly the networks the C&E marks, nothing extra.
- 05 Output Feedback: 90 units, 92 coils each driven once from the area its C&E AREA sheet gives; every feedback
  read in its own unit's network (the swiveler relays of unit 0034 and the maintenance pairs included); each ERROR
  to the unit's own 03_FDBACK_RAW member. 06 Feedback Error maps RAW -> FDBACK one to one.

## Defects (the P-018 fix list)
1. 05 Output Feedback: template variants 2-12 name their instance `!!instanceOf-FDBACK$$`, variant 1
   `!!instanceOf-F_FDBACK$$`; the builder fills only the latter, so the 3 FVT networks on variants 2 / 4 (unit 0034,
   the two maintenance zones) get an EMPTY instance name. Openn3App substitutes an empty key with '' and passes its
   gate (no placeholder left), so TIA rejects the network. This is what `test_blocks
   fdback_reproduces_12_template_networks` has been failing on (PL4: "pre-existing").
2. 04 ESTOP: AREA 1 took variant 06 (doors + breakers + encoder, TIME_DEL 10 s) though it has no doors (an empty
   `02_COM.` operand in the power-cut AND), while AREA 1_TRIB / AREA 1_TRIH took 05. User: the two sub-areas are the
   sorters and take the sorter variant (06, encoder health of their own sorter: TRIB -> 01, TRIH -> 02); AREA 1
   (e-stops + breakers) takes 04. The 10 s delay sits in variant 06.
3. 08 Gate Manager (8 doors), against the old `02_Safety_Door` FB (TIA export, F_LAD):
   - E-STOP = DIAG AND CH1 AND CH2 (net 1): CH2 is left OPEN, so the door never reads closed -> 07_DOOR SAFE_STATE
     never TRUE -> the 1_TRIB / 1_TRIH DOORS flags FALSE -> those areas never power. With the 1oo2 F-DI pair, CH2 is
     the same input as CH1.
   - Solenoid = Sorter_Door AND NOT Sorter_Running_from_MSC AND Sorter_Stop_from_Encoder AND Open_Request (net 2):
     Sorter_Door = AlwaysFALSE -> never unlocks; Diag_Alarm ORs NOT Sorter_Door (net 4) -> a permanent alarm.
     User: sorter doors (TRUE); the open request comes over the IOC interface (the old program: "DOOR OPEN REQUEST
     ... FROM LOW/HIGH SORTER"); the standstill is the received SPEED_STATE_REC (UDT SORTER_SPEED_STATE:
     SORTER1_TRIB_STOPPED, SORTER1_TRIB_ENCODER_BROKEN, SORTER2_TRIH_STOPPED, SORTER2_TRIH_ENCODER_BROKEN).
   - The "sorter running" tag was put on the two speed-transfer rows (whose variant ignores it), not on the doors.
4. Zone FDB group (`ZONE_GROUPS` FDB reads `("KQ",)`): the maintenance outputs are typed KQ1/2 / KQ2/2, so their
   feedback errors are in no area's FDB network - a welded maintenance contactor never stops AREA 1.
5. Speed: 07 Speed Control writes `04_SPEED."Safety Encoder Failure [ =TRIB-EN02-B1R ]"`, a member the 520 DB does not
   have; 04 / 07 / 08 reference `SPEED_STATE_REC.SORTER_0x_STOPPED` / `.RCV_DATA.SORTER_01_ENCODER_HEALTHY`, names
   the received type does not have (and HEALTHY is the inverse of the type's ENCODER_BROKEN).
6. Interfaces (400): an interface instance is triggered only by a row typed IOC; `parse_instance('FVT_GENERIC-03')`
   gives machine type `FVT` (leading letters only) -> the `<GENERIC>` template sheet instead of `FVT_GENERIC`.
7. Zone networks' titles: the sub-area networks take the CONCEPT entry of another area ("AREA 1_TRIB PB - AREA 2
   (CAROUSEL)") - see P-016.
8. Validation 150 `diag_invalid` fires on 101 OUTPUTS (90 contactor outputs, 11 area-status outputs): outputs carry
   no diagnosis slot.
9. Not generator code, recorded for the FVT run: the SFB stations got no I/O addresses (C-028); the QBAD tags the
   output-feedback networks read do not exist (P-017, user decision D4: the input at the output's offset); the
   PN/PN couplers get no transfer areas (no card rows, no address template).

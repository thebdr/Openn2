# C-034 - Lossless IF_ sheet insertion - evidence

## Origin (2026-10-09, P-019): the openpyxl re-save, measured on FVT
The user asked to enable the I/O-List interface insertion. The first real insert (the PL3 port: openpyxl loads
the whole I/O List, adds the sheets, re-saves, then patches the formula caches back, then `freeze_arrays`)
was measured against a cell-level snapshot of `8FVT_IO0100- IO List Safety_R0.3.xlsx`:
- all 104 live dynamic-array formulas removed (the `freeze_arrays` post-pass: 94 in `NET SAFETY 192.168.20`
  AM/AN - the `RIGHT(R,1)&TEXT(AI,"000")` / `AM&"_"&TEXT(AJ,"00")` keys - and 10 `=T_Types[...]` columns in
  `FamilyCheck` frozen to their values); `xl/metadata.xml` dropped;
- the two threaded comments turned into plain notes (`threadedComments`, `persons` dropped);
- the Claude-for-Excel add-in binding (`webextensions`), `featurePropertyBag` and the printer settings dropped;
- 2,338 empty-text cells turned into empty cells.
Formulas, cached values and fills of every other cell survived (40,404 cells). The document was restored
byte-identical (the lossy result kept beside it as `...R0.3.xlsx.after-IF-insert-LOSSY-20261009`) and the FVT
switch set back OFF.

## The design (src://Pipeline5App/pipeline5/documents/xlsx_sheet_graft.py)
The target is never re-serialised. Each IF_ workbook's first sheet is GRAFTED: its worksheet XML copied as a new
part (style indices remapped into the target, shared strings -> inline strings, the grafted tables' names
rewritten in its formulas, `tabSelected` / `codeName` dropped, the address caches seeded), its table parts
renamed + re-identified (dxf / cell-style references and calculated-column formulas dropped - they point into
the source workbook / at the old name), and four bookkeeping parts APPENDED to: `xl/workbook.xml` (+ `<sheet>`
last, + `fullCalcOnLoad`), its rels, `[Content_Types].xml`, `xl/styles.xml` (fonts / fills / borders / number
formats / cell formats / conditional-format dxfs appended at the ends of their collections, an equal entry
reused, only the counts change). Every other part is written back from its own bytes. One atomic write.

## Spike (2026-10-09): what Excel needs - a private Excel 16 instance via COM, read-only, CHECK only
- Repair detector, calibrated: with `DisplayAlerts=False`, `Workbooks.Open` of a file Excel would repair RAISES
  ("Open method of Workbooks class failed") instead of prompting. Calibration file = the grafted FVT copy with
  ONE table column renamed (`Category` -> `CategoryX`, header cell mismatch): the open raised. The original
  I/O List (the control) and the grafted copy: opened, no raise, no repair log in %TEMP%.
- `fullCalcOnLoad` is NEEDED: the same grafted copy with the flag removed opens fine, but Excel shows the IF_
  sheets' uncached formulas EMPTY (`I/O Address Side 2` N2, the FVTGENERIC offset/bit chains K3/L3, the SORTER
  `Output Format` AJ2) - only the seeded Side-1 addresses show. With the flag: N2 `I.10.0.0`, K3/L3 `0`/`1`,
  AJ2 `Q<base+offset>/.<bit>`. (openpyxl's re-save had set the flag too - it writes `fullCalcOnLoad="1"`.)
- The calcChain stays untouched: Excel accepts the new formula cells it does not list (no repair).
- docProps/app.xml stays untouched (its TitlesOfParts lists 5 sheets of 12): Excel does not validate it.

## The unit-test fixture through Excel (2026-10-09)

other part dropped one at a time still refused; only the blob mattered). It now carries a minimal well-formed

landscape. The fixture after the test's grafts (two sheets from `_make_rich_if` + the shared-strings source) opens
too, no repair: `IF_SORTER-01`, `IF_SORTER-02` (tables `DT_IF_SORTER_01` / `_02`), `IF_S` (B1 `bold rest`),

workbook Excel accepts, not only one openpyxl reads.
